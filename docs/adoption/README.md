This route helps an adopter or technical evaluator answer a practical question:

> Which existing Fork evidence is relevant to my purpose, what standing does it already have, what remains research or repair, and where can I inspect the exact source record?

This is a **presentation route over existing evidence**. It does not relocate artifacts, create admission, or change native standing.

### Integration and adoption reasoning

The adoption projection organizes the existing corpus into five bands so a reviewer does not have to infer standing from repository proximity:

- **A — Adoption Baseline:** separately bound baseline/admitted surfaces.
- **B — Qualified / Bounded Proof Evidence:** useful bounded evidence whose qualifications and packaging standing remain visible.
- **C — Active Research:** candidate research and executed candidate evidence without silent promotion.
- **D — Repair / Excluded:** known defects, residuals, or unresolved governance questions that should not enter an adoption route by implication.
- **E — Historical / Preservation:** predecessor states, adverse results, exterior observations, and correction lineage.

The machine projection remains the source for exact band entries. The bands are not a new standing system.
